## ขอบเขตที่ยืนยัน

- เอาเพดานอายุออก กรอกเป็นปีเต็มเหมือนเดิม ไม่ถามเดือน
- เอา tooltip/ป้ายชื่อไอเท็ม เช่น Pizza หรือ Apple ออกจาก gameplay
- เพิ่มไอเท็มออกกำลังกาย เก็บด้วย gesture กระโดด และลด BMI **จำลอง** ของตัวละคร
- คงรอบจริง 3 นาที, 10 ประตูคำถาม, ผิดติดกัน 3 ข้อจบเกม และประตูข้อ 10 เป็นเส้นชัย
- คงการเปลี่ยนเลน A/D, ลูกศร, swipe และกล้อง รวมถึง pause → calibrate → ยกมือค้าง → countdown เมื่อกล้องหลุด

เอกสารนี้แทนข้อกำหนดเดิมเรื่องไม่มีกระโดดและป้ายชื่อไอเท็มใน [แผนรอบก่อน](food-fit-fun-next-iteration.md) เฉพาะส่วนที่ขัดกัน ค่าตัวเลขด้านล่างเป็นค่าเริ่มต้นเสนอสำหรับ playtest

## FFF-08 — อายุไม่มีเพดาน

1. ตามคำยืนยันล่าสุด ลบทั้ง `min` และ `max` ในช่องอายุ ไม่มีช่วงอายุผลิตภัณฑ์บังคับ
2. รับเฉพาะปีเต็มที่ไม่ติดลบ (รวม 0 ปี) และคูณเป็นเดือนภายในได้อย่างปลอดภัย ปฏิเสธค่าว่าง ทศนิยม NaN/Infinity และค่าที่เกินความแม่นยำของตัวเลข ไม่ใช้เพดานอายุผลิตภัณฑ์แทน validation นี้
3. โปรไฟล์เดิมอ่านได้ตามเดิม แก้ข้อความ “รองรับอายุ 9–12 ปี” ที่ทำให้เข้าใจว่าผู้เล่นอายุมากกว่าเล่นไม่ได้
4. แยก **อายุที่เล่นได้** ออกจาก **อายุที่ข้อมูลอ้างอิงสุขภาพรองรับ**: BMI ตัวเลขยังคำนวณจากส่วนสูงและน้ำหนักได้ แต่หากไม่มีข้อมูลอ้างอิงตามวัย ให้แถบเป็นสีกลางและแสดง “ยังไม่มีช่วงอ้างอิงสำหรับอายุนี้” ไม่แสดงผลสมส่วน/สูง/ต่ำโดยเดาเกณฑ์
5. สูตรพลังงานที่มีอยู่ใช้สำหรับช่วง 9–12 ปีเท่านั้น เพิ่ม guard ก่อนใช้สูตร อายุอื่นให้ `eer: null` พร้อมเหตุผล ไม่ขยายสูตรเดิมไปทุกวัยโดยลบ validation อย่างเดียว
6. เปลี่ยนสัญญา question bank ให้ขอบบนของ `ageRange` เป็น `null` ได้ เช่น `[0, null]` หมายถึงทุกอายุที่รับข้อมูลได้ ออก schema ใหม่และรองรับไฟล์ schema เดิมที่ยังมีช่วงอายุจำกัด
7. ตรวจเนื้อหา demo ที่เป็นความรู้ทั่วไปแล้วกำหนดช่วงแบบไม่มีขอบบนอย่างชัดเจน พร้อมเพิ่ม content version ส่วนธนาคารคำถามที่ผู้ดูแลตรวจแล้วต้องคงช่วงอายุของผู้เขียน ไม่ลบตัวกรองทุกข้อทิ้ง
8. หากธนาคารที่เลือกมีคำถามเหมาะกับอายุไม่ครบ 10 ให้แจ้งเหตุผลและให้เลือกชุดทดลองทั่วไป ไม่ดึงคำถามผิดช่วงวัยเพื่อเติมให้ครบ ไม่เปลี่ยนกติกาคำถามไม่ซ้ำในรอบ

**จุดแก้**: `ProfileForm.tsx`, `assessment.ts`, `QuestionDeck.ts`, question bank types/parser และข้อความหน้าผลรอบ

**ตรวจรับ**: อายุ 13, 18 และ 60 บันทึก/เปิดโปรไฟล์/เริ่มชุดทดลองได้; อายุ 9–12 ยังทำงานเดิม; ข้อมูลอ้างอิงไม่พร้อมแสดงสถานะตรงจริง; bank เดิมนำเข้าได้และยังรักษา age eligibility

## FFF-09 — เอาป้ายชื่ออาหารออก

- ลบ floating plaque ทั้งชื่อและข้อความผลของไอเท็มจาก `GameEngine3D.addLearningItemLabel()` รวมถึง tooltip/hover ที่ระบุชื่ออาหาร
- ไม่แสดงชื่ออาหารซ้ำใน pickup feedback ระหว่างเล่น เหลือเอฟเฟกต์ เสียง และข้อความสั้น เช่น “BMI จำลอง +0.4” ตาม delta จริง
- เก็บชื่อและชนิดไอเท็มไว้ใน catalog, บันทึกรอบ และผลสรุป เพื่อใช้ทบทวน/analytics ไม่ลบข้อมูลภายในตามการซ่อน UI
- แบบฝึกยังมีคำแนะนำการกระทำ เช่น “ขยับไปเลนที่ไฮไลต์” แต่ไม่มี popup อธิบายว่าไอเท็มนี้คือ Apple/Pizza
- คงคำถามและคำตอบบน quiz gate เพราะเป็นเนื้อหาโจทย์ ไม่ใช่ tooltip ของไอเท็ม
- ทำโมเดล สี และ silhouette ให้แยกชนิดได้โดยไม่ต้องมีชื่อ อ่านภาพได้ทั้งมือถือและกล้องระยะไกล

**ตรวจรับ**: ไม่มีป้ายชื่อเหนือตัวไอเท็มหรือชื่ออาหารใน feedback ระหว่างวิ่ง; quiz ยังอ่านได้; texture ของป้ายเดิมไม่ค้างหลัง retry

## FFF-10 — ไอเท็มออกกำลังกายและกติกากระโดด

### รูปแบบการเล่น

- เพิ่ม 3 รูปแบบ: รองเท้ากีฬา ดัมเบล และเชือกกระโดด ใช้สี/วงแหวนรูปคนกระโดดแบบเดียวกันเพื่อสื่อว่าเป็นไอเท็มประเภทออกกำลังกาย ไม่ใส่ชื่อ tooltip
- วางลอยสูงกว่าอาหาร ผู้เล่นต้องอยู่เลนเดียวกันและกระโดดในช่วงเก็บ จึงได้ไอเท็ม วิ่งชนบนพื้นไม่เก็บ
- ไม่เก็บได้ให้ผ่านไป ไม่มีหักคะแนน ไม่มี Game Over และไม่นับเป็นการข้ามมื้ออาหาร จึงยังไม่มีสิ่งกีดขวางบังคับกระโดด
- ค่าเริ่มต้นเสนอ: รอบละ 5 จุด กระจายในช่วงระหว่างคำถาม 2–9; จุดกระโดดไม่ทับแถวอาหาร และมีเลนอื่นให้เลือกผ่านได้เสมอ
- เว้นจุดอย่างน้อย 6 วินาทีจากจุดกระโดดก่อนหน้า และห่างจาก quiz approach ทั้งก่อน/หลังอย่างน้อย 3 วินาที ไม่ให้ต้องอ่านคำถามและกระโดดพร้อมกัน
- แสดงสัญญาณวงแหวนก่อนถึงจุดประมาณ 1.5–2 วินาทีเพื่อให้เตรียมตัว เก็บด้วยช่วง action ที่กำหนดใน session ไม่ใช้การชน model จาก renderer เป็นตัวตัดสินผล

### ผลต่อ BMI จำลอง

- เก็บสำเร็จลด `balance` 20 จุด ค่าเริ่มต้นจากตัวคูณปัจจุบันเท่ากับลด BMI จำลอง 5% ของ BMI เริ่มต้น เช่น เริ่ม 20 ลด 1.0 ต่อครั้งก่อนชนขอบ
- ใช้ขอบ `balance` เดิม -100 ถึง +100, คำนวณ delta หลัง clamp และแสดงเฉพาะผลที่เกิดจริง แต่ละไอเท็มส่ง event/เสียง/คะแนนครั้งเดียว
- การกระโดดเปล่าไม่ลดค่า และการกระโดดค้างหลายเฟรมไม่สะสมผล ไม่มีโบนัสใหม่สำหรับทำค่าให้ต่ำที่สุด; คะแนนสมดุลยังใช้กติกาเดิม
- ลดได้แม้ต่ำกว่าค่าตั้งต้นแล้ว จึงต้องเลือกเก็บอย่างพอดี แถบ/ผลรอบต้องสื่อค่าต่ำเกินด้วย ไม่เปลี่ยนทุกการลดให้เป็น feedback ว่า “สุขภาพดีขึ้น”
- ข้อมูลส่วนสูง น้ำหนัก BMI จริง และผลอ้างอิงของโปรไฟล์ไม่ถูกแก้จากไอเท็ม ผลรอบแยก “BMI เริ่มต้น” กับ “BMI จำลองในเกม” ชัดเจน
- เพิ่ม body/level version สำหรับกติกาใหม่นี้ แยก high score ต่างกติกา และเพิ่มจำนวน exercise เก็บได้/พลาดกับ jump attempts ในสรุปรอบแบบ aggregate

### Input และการตรวจจับจากกล้อง

- Camera: กระโดดจริงแบบเบา ๆ ใช้การขยับขึ้นและกลับลงของลำตัว เทียบกับท่ายืนปกติ ไม่ใช้การยกมือแทนกระโดด
- เพิ่ม `JumpGesture.ts` แยกจาก `HandHoldStart` และ lane mapping โค้ด `PoseMapper.jump` เดิมหมายถึง pulse ยกมือ จึงห้ามนำมาเชื่อมเก็บ exercise ตรง ๆ
- Normalize ระยะด้วยขนาดลำตัวจากไหล่/สะโพก ตรวจความมั่นใจและการเคลื่อนขึ้นร่วมกันของสองตำแหน่ง มีช่วง neutral → rising → landed → rearmed; การย่ออย่างเดียว/ยกมืออย่างเดียว/ภาพสั่นต้องไม่ผ่าน
- ค่าเริ่มต้นเสนอ: ขยับขึ้นอย่างน้อย 12% ของความยาวลำตัวจาก baseline, กลับลงใน 0.15–1.2 วินาที และ cooldown 700ms หลังลงพื้น ปรับจาก recording/playtest ไม่ใช้จำนวนเฟรมคงที่
- Emit jump หนึ่งครั้งเมื่อมีหลักฐานขึ้นที่เชื่อถือได้ ลงพื้นเพื่อ rearm; หาก pose stale เกิน 250ms หรือ tracking lost ให้ยกเลิก gesture และไม่สั่งเก็บจากค่าค้าง
- Detector ต้องทำงานกับ fallback 8fps โดยไม่เพิ่ม FPS ทั้งระบบ ใช้ timestamp และช่วงเวลา; ตรวจสถานการณ์ตัวอยู่ไกล/สะโพกหลุด/กล้องสั่นบนอุปกรณ์จริง
- Calibration ตั้ง baseline ใหม่เมื่อเริ่มหรือ recovery และ clear jump window ตอน pause/countdown ไม่สะสมเวลาหรือรับคำสั่งกระโดดระหว่างนั้น
- Manual: Space / ลูกศรขึ้นเพื่อกระโดด; มือถือ swipe ขึ้น (แนวตั้งชัดเจน) เพื่อกระโดด ขณะที่ swipe แนวนอนยังเปลี่ยนทีละเลน หนึ่ง gesture ให้หนึ่ง action ไม่เปลี่ยนเลนและกระโดดพร้อมกันจาก swipe เดียว
- มีปุ่มกระโดดสำหรับ manual touch เป็นทางเลือก กรณีกล้องใช้ไม่ได้สามารถเปลี่ยน manual ตาม flow เดิม

### Session และภาพตัวละคร

- เพิ่ม command/action state สำหรับ jump ใน `RunSession` ให้ทุก input ใช้กติกาและช่วงเก็บเดียวกัน ค่าเริ่มต้นเสนอ jump window 0.65 วินาที และ cooldown 0.7 วินาที
- ให้ `renderLearning` อ่าน jump progress จาก snapshot เพื่อยกตัว/งอเข่า/ลงพื้น เงาตามระดับความสูง ไม่เรียก legacy physics ซ้อนเพราะ renderer ปัจจุบันจัดตำแหน่ง y เอง
- ไอเท็ม exercise ต้องมี success/miss event แยกจากอาหาร เอฟเฟกต์สำเร็จใช้วงแหวน/ประกายพร้อมตัวเลขจริง ไม่บัง quiz; reduced-motion ลดเอฟเฟกต์ตกแต่งแต่ยังเห็น action สำคัญ
- ใช้ seeded layout และ collision ที่เล่นซ้ำได้ ทดสอบเก็บผ่าน delta time ต่างกัน และไม่ปล่อยให้การกระโดดเปลี่ยนกติกาเลือกประตูคำตอบ

**จุดแก้**: `ItemCatalog.ts`, `RunSession.ts`, learning types, `JumpGesture.ts` ใหม่, `LearningGame.tsx`, `GameEngine3D.ts`, `LearningAudio.ts`

## FFF-11 — ฝึกกระโดดครั้งเดียว แล้วข้ามรอบต่อไป

- เพิ่มขั้นกระโดดใน `GuidedTutorial` หลังฝึกเลือกเลน/เก็บไอเท็ม ก่อนฝึกประตูคำถาม
- ใช้ flow เดิม: transition ช้า → pause → ข้อความใหญ่ “กระโดดเบา ๆ เพื่อเก็บสัญลักษณ์นี้” → ตรวจ action ถูกและ pose สด → ปล่อยฉากเดินต่อ เก็บไอเท็มสาธิตครั้งเดียว
- เวลาที่ฉากเคลื่อนรวมประมาณ 20–30 วินาที; เวลารอผู้เล่นไม่ถูกบังคับให้นับรวมจนต้องรีบทำ ไม่หักเวลารอบจริง 180 วินาที
- โปรไฟล์ที่เคยเรียนเวอร์ชันเดิม: แสดงเฉพาะบทกระโดดใหม่ครั้งเดียว ไม่สอนเลน/อาหาร/quiz ซ้ำ โปรไฟล์ใหม่เรียนครบทุกขั้น รอบถัดไปข้ามอัตโนมัติ
- เพิ่ม tutorial version และ migration: completed/skipped เวอร์ชันเดิมยังเป็นหลักฐานว่าผ่านขั้นเก่าแล้ว แยกสถานะขั้น jump ใหม่ พร้อมปุ่มข้ามและฝึกซ้ำใน Settings
- Tutorial ไม่บันทึกคะแนน/ไอเท็ม/คำถามลงผลรอบจริง; กล้องหลุดใช้ recovery เดิม กลับมาต่อขั้นเดิมและรอกระโดดใหม่

## ลำดับพัฒนาและตรวจรับ

1. ตรวจ working tree และอ่านแผนนี้ร่วมกับแผนเดิม → ทำ FFF-08 อายุและ bank migration

**Tests ที่จำเป็น**

- อายุเกิน 12 บันทึกได้; invalid age ยังถูกปฏิเสธ; EER นอกช่วงไม่ใช้สูตรเดิม; ไม่มี reference ใช้ meter สีกลาง
- Bank schema เก่า/ใหม่, ขอบบน null, eligibility, demo 10 ข้อไม่ซ้ำ, bank ไม่ครบแจ้งเหตุผล
- Jump detector: neutral/up/down, ยกมือ, ย่อ, landmark noise, stale/lost, rearm/cooldown, 8fps/15fps; hold-start ไม่ถูกสั่งโดย jump
- Exercise: เลนถูก+action window เก็บได้ครั้งเดียว; เลนผิด/ไม่กระโดด/กระโดดเร็วหรือช้าไม่เก็บ; miss ไม่ลง meal penalty; delta/clamp ถูก; profile ไม่เปลี่ยน
- Pause/recovery ระหว่าง jump ไม่เก็บจากคำสั่งเก่า; ระยะ/เวลา/คะแนนหยุด; quiz 10 ประตูและแพ้ 3 ข้อติดยังถูกต้อง
- Tutorial migration: ผู้เล่นเก่าเห็นเฉพาะขั้นใหม่ครั้งเดียว; ผู้เล่นใหม่ครบ; retry/reload ข้าม; practice ไม่ปนผลรอบจริง

**Device QA**: iPhone/iPad Safari และ Android Chrome ที่ 8fps fallback/worker ตามความสามารถจริง; ตรวจจับกระโดดเบา ๆ ทั้งใกล้และไกล, มือยกไม่เป็น jump, กล้องหลุดแล้วต่อได้, swipe ไม่ชนคำสั่ง, โมเดลลงพื้นและเงาไม่ผิดตำแหน่ง รายงานอุปกรณ์ที่ทดสอบและข้อจำกัดตรงจริง
