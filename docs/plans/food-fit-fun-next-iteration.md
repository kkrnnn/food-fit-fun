## เป้าหมายและขอบเขต

ทำให้เด็กเข้าใจวิธีเล่นตั้งแต่เริ่ม เห็นและได้ยินผลของการเลือกชัดขึ้น และเล่นด้วยกล้องจากระยะไกลได้สะดวก โดยเพิ่มเสียง ไอเท็ม ช่วงสอนเล่น เอฟเฟกต์ และการยกมือค้างเพื่อเริ่มเกม

ค่าตัวเลขใหม่ในเอกสารนี้เป็น **ค่าเริ่มต้นเสนอสำหรับ playtest** ปรับได้จากการทดลองเล่น ไม่ใช่สูตรสุขภาพหรือข้อกำหนดที่ผู้ใช้ยืนยันแล้ว คำ Objective ตัวจริงจะได้รับภายหลัง

คงกติกาเดิม: รอบจริงประมาณ 180 วินาทีขณะเกมเดิน, 10 คำถามไม่ซ้ำในรอบ, คำถามตามระยะทาง, ประตูคำตอบไม่ pause เกม, ผิดติดกัน 3 ข้อ Game Over, ประตูข้อ 10 เป็นเส้นชัย และถ้าข้อ 10 ทำให้ผิดติดกันครบ 3 ให้ Game Over ก่อนผล completed ไม่มีสิ่งกีดขวางหรือการกระโดดเพิ่ม

คง A/D และลูกศรซ้ายขวาแบบเลื่อนทีละเลน รวมถึง swipe บนมือถือ เก็บข้อมูลในเครื่องตามเดิม Shared database ยังเป็น backlog ไม่รวมในงานนี้

## Flow ที่จะได้

1. เปิดเกม → modal มีเฉพาะ Objective พร้อม placeholder → ติ๊กอ่านแล้ว → OK
2. หน้า Food Fit Fun → Play / Settings → เลือกหรือกรอกโปรไฟล์เดิม
3. Manual: เริ่มด้วยปุ่ม / Camera: เปิดกล้อง ตั้งท่ากลาง แล้วแสดง “ยกมือข้างใดข้างหนึ่งค้างไว้เพื่อเริ่ม”
4. Camera: วงแหวนคืบหน้าขณะยกมือค้าง 1.5 วินาที → ยืนยันสำเร็จ → countdown 3–2–1
5. ครั้งแรกของโปรไฟล์เข้าบทฝึกแบบ transition → หยุดฉาก → แนะนำ → รอผู้เล่นขยับถูกทาง → เดินต่อ ทำครบแล้วบันทึกและเข้าสู่รอบจริงอัตโนมัติ รอบถัดไปข้ามบทฝึกอัตโนมัติ ไม่ต้องเลือกข้ามทุกครั้ง
6. รอบจริง → ผลตอบคำถามและผลเก็บไอเท็มชัดเจน → เส้นชัย / Game Over → ผลรอบและทบทวนคำตอบ

## FFF-01 — Objective และตัวหนังสืออ่านง่าย

**งาน**

- ลบหัวข้อและข้อความ Introduction จาก modal รวมถึงข้อความ checkbox ที่อ้างถึง Introduction
- เหลือหัวข้อ “Objective” และ Lorem ipsum ชั่วคราว เก็บข้อความไว้ในค่าหรือ component เดียวเพื่อเปลี่ยนภายหลัง
- คง checkbox และ OK เปลี่ยนข้อความเป็น “อ่าน Objective แล้ว” คง focus trap และการห้ามคลิกฉากหลัง
- สร้าง typography tokens สำหรับข้อความทั่วไป หัวข้อ คำถาม คำตอบ และ feedback แทนแก้ font-size กระจัดกระจาย
- ค่าเริ่มต้น manual: body 18–20px, คำถาม 26–32px, คำตอบ 22–26px; camera บน tablet/desktop: คำถาม 36–44px, คำตอบ 28–34px, คำสั่งตั้งท่า/ยกมือ 28–36px
- จอมือถือแคบใช้ responsive layout: คำถาม 26–30px, คำตอบ 22–26px ห้ามย่อจนอ่านไม่ได้เพื่อฝืนให้พอดี คำถามยาวต้องจัดบรรทัดและจำกัดความยาวเนื้อหาตามพื้นที่จริง
- คำตอบด้านบนอยู่เรียงตำแหน่งเดียวกับประตูทั้งสาม ห้ามใส่เลข 1/2/3 หรือซ้าย/กลาง/ขวากลับมา
- แบ่งพื้นที่ HUD ชัดเจน: คำถามและคำตอบด้านบน, เส้นทางและประตูตรงกลาง, BMI/สถานะด้านล่าง, กล้องขนาดเล็กไม่บังคำตอบ เอฟเฟกต์ไม่ทับข้อความ

**ตรวจรับ**: Objective-only modal ทำงาน; ตัวอักษรไทยไม่ถูกตัด; คำตอบยาวอ่านครบทั้งสามช่อง; ทดสอบมือถือ portrait/landscape และ tablet; โหมดกล้องอ่านคำถามจากระยะประมาณ 2–3 เมตรบนอุปกรณ์จริงได้ หากมือถือเล็กเกินให้แนะนำวางใกล้ขึ้น ไม่อ้างว่า CSS รับประกันระยะอ่านได้

**จุดแก้**: `src/features/learning/LearningGame.tsx`, `LearningGame.css`

## FFF-02 — ยกมือค้างเพื่อเริ่มในโหมดกล้อง

**งาน**

- เพิ่ม state machine แยกจาก session: `waiting_camera → calibrating → ready → holding → countdown → playing`
- เริ่มรับ gesture ได้เมื่อโปรไฟล์พร้อม กล้องโหลดโมเดลสำเร็จ ตั้งท่ากลางสำเร็จ และมี pose สดที่เชื่อถือได้ หน้ายัง loading/error ต้องแสดงเหตุผล ไม่วน “กำลังโหลด” โดยไม่มีทางออก
- หลังเข้า ready ต้องเห็นมือลงก่อนหนึ่งครั้ง เพื่อไม่ให้มือที่ยกค้างระหว่างตั้งกล้องสั่งเริ่มทันที
- ใช้ข้อมือเหนือไหล่เป็น predicate ตรวจความมั่นใจของไหล่/ข้อมือ ใช้ normalization ตามลำตัวและ hysteresis ลดการสั่น เก็บมือข้างที่เริ่ม hold; เปลี่ยนข้างให้เริ่มจับเวลาใหม่
- ค้าง 1.5 วินาทีต่อเนื่อง แสดงวงแหวนเติมรอบไอคอนมือ ข้อความ “ค้างไว้อีกนิด” และเอฟเฟกต์ยืนยันเมื่อครบ
- ลดมือต่ำกว่าเกณฑ์ หลุดกรอบ pose เก่ากว่า 250ms เปิด modal สลับโหมด ซ่อนแท็บ หรือออกจากหน้า → reset progress; ไม่สะสมเวลาช่วงที่ไม่ได้รับ pose
- ทำงานกับ fallback 8fps ได้ ใช้ elapsed time จากเฟรมที่ผ่าน validation ไม่ใช้จำนวนเฟรมเป็นเวลา
- เมื่อครบให้เริ่มเพียงครั้งเดียว ถ้าหลุดระหว่าง countdown ให้กลับ ready และตั้งใจยกมือใหม่ ห้ามเริ่มวิ่งโดยไม่มี tracking
- ระหว่างเกม gesture นี้ไม่มีผล ไม่สั่งเริ่มซ้ำ ไม่ผูกกับ jump เดิม; เมื่อ tracking หลุด ให้ pause รอบเดิม → recalibrate ท่ากลาง 1.5 วินาที → ลดมือและยกมือค้าง 1.5 วินาที → countdown 3–2–1 → เล่นต่อจุดเดิม ใช้ได้ทั้งบทฝึกและรอบจริง ไม่สร้าง run/ชุดคำถามใหม่ ไม่รีเซ็ตคะแนนหรือระยะ คงปุ่มเริ่ม/วิธี manual เป็นทางเลือกเมื่อกล้องไม่พร้อม
- เหตุ tracking lost ที่ส่งมาซ้ำระหว่าง recovery ต้องไม่เริ่ม calibration ใหม่ซ้ำ; ถ้าหลุดอีกระหว่าง countdown ให้กลับมาตั้งท่าและยกมือใหม่

**สถาปัตยกรรม**: เพิ่มโมดูลเล็ก เช่น `HandHoldStart.ts` รับสถานะ pose/time/readiness และคืน progress/one-shot completion; ใช้ landmark จาก `PoseMapper` โดยไม่เปลี่ยน semantics ของ legacy `jump` ที่ปัจจุบันเป็น pulse สั้น ไม่ใช่ hold

**ตรวจรับ**: ยกค้างครบเริ่มครั้งเดียว; ยกสั้น/มือสั่น/สลับมือ/เฟรมขาดไม่เริ่มผิด; ยกมือขณะเล่นไม่กระทบเกม; ทดสอบ Safari iPhone/iPad และ Chrome Android จริง; คงการแก้ MediaPipe fallback ที่มีอยู่

## FFF-03 — บทฝึกหยุดแนะนำ แล้วขยับถูกทางเพื่อเดินต่อ

**งาน**

- ใช้บทฝึกแยกก่อนรอบจริงแบบรอการกระทำ ไม่มีเวลาฝึกตายตัว 20–30 วินาที ไม่มี timeout ที่พาไปขั้นถัดไปเอง ไม่นับรวม 180 วินาที คะแนน high score, itemCounts หรือ exposure ของคลังคำถาม
- แต่ละจุดใช้ flow `เดินเข้าจุดสอน → transition ชะลอจนหยุด → แสดงคำแนะนำ → รอการกระทำที่ถูก → ยืนยันสำเร็จ → transition เดินต่อ` ใช้ระยะ transition สั้นประมาณ 300–500ms เป็นค่าทดลอง
- ระหว่างหยุดสอนให้ระยะทาง ไอเท็ม ประตู และเวลาจำลองหยุด แต่ camera detection, input เปลี่ยนเลน, UI และการตรวจคำตอบฝึกยังทำงาน ห้ามใช้ pause แบบปิด input จนเด็กทำตามไม่ได้
- สอนทีละเรื่องผ่านการลงมือ: เลื่อนหนึ่งเลน → เก็บไอเท็มและดูผล → เลือกประตูคำตอบทดลองหนึ่งข้อ
- แสดง tooltip สั้นครั้งละอัน พร้อมไฮไลต์เป้าหมาย เช่น “ลองขยับไปหาแสง”, “ขยับไปเลนผลไม้”, “เลือกคำตอบแล้วอยู่ในเลนนั้น” เปลี่ยนข้อความตาม camera/manual/swipe และไม่เพิ่มปุ่มลูกศรบนจอกลับมา
- ขั้นเลือกเลน: เริ่มจากเลนที่ต่างจากเป้าหมาย เมื่อผู้เล่นขยับถึงเลนเป้าหมายให้ยืนยันแล้วเดินต่อ; camera ต้องมี pose สดและอยู่เลนนั้นนิ่งประมาณ 300ms เพื่อกันผ่านเพราะ tracking สั่น
- ขั้นเก็บไอเท็ม: หยุดก่อนถึงไอเท็ม ให้ขยับเข้าเลนที่กำหนด แล้วปล่อยฉากเดินจนเก็บจริง จึงแสดงผลบนแถบสมดุลและไปจุดสอนถัดไป
- ขั้นประตูทดลอง: หยุดก่อนประตู แสดงคำถามและรอเลือกเลนคำตอบที่ถูก จึงเดินผ่านประตู; ถ้าเลือกผิดให้คำใบ้และลองใหม่ ไม่ลงโทษ การหยุดนี้ใช้เฉพาะบทฝึก ส่วนประตูในรอบจริงยังวิ่งต่อเสมอ
- ขยับผิดหรือยังไม่ขยับให้คงขั้นเดิมพร้อมคำใบ้ ไม่บังคับกด “ถัดไป” ไม่มี Game Over ในบทฝึก และแต่ละขั้นสำเร็จได้ครั้งเดียว
- ใช้คำถามฝึกแยกจากชุดจริง แสดงว่าเป็น “ลองเล่น” ตลอดช่วง; ก่อนเริ่มรอบจริงรีเซ็ต BMI จำลองและ session ทั้งหมดกลับค่าเริ่มต้น
- เซฟสถานะบทฝึกตาม playerId ใน persistence ของเครื่องเดิม เช่น `{ status: 'completed' | 'skipped', tutorialVersion, updatedAt }` และเก็บสำเนาใน state ของ session เพื่อไม่ให้สอนซ้ำเมื่อ storage เขียนไม่ได้
- บันทึก completed ทันทีที่ผ่านขั้นสุดท้าย ก่อนเข้าสู่รอบจริง ไม่รอให้เล่นจบ ดังนั้น Game Over, retry, กลับเมนูกด Play, reload หรือเปิดเว็บครั้งถัดไปต้องข้ามบทฝึกอัตโนมัติเมื่อใช้โปรไฟล์เดิม
- ถ้าผู้เล่นกด “ข้ามการฝึก” ให้บันทึก skipped และไม่เสนอฝึกซ้ำอัตโนมัติ ถ้าออกกลางบทฝึกโดยไม่ได้ผ่านหรือข้าม ยังถือว่าไม่จบและเสนอฝึกในครั้งต่อไป
- เพิ่ม “ฝึกอีกครั้ง” ใน Settings เป็นการเปิดบทฝึกโดยตั้งใจ ไม่ล้างสถานะที่เคยผ่าน/ข้าม หากออกกลางการฝึกซ้ำ รอบปกติยังข้ามบทฝึกเหมือนเดิม โหมดกล้องต้องทำบทฝึกต่อได้โดยไม่กลับมากดจอ
- โปรไฟล์ใหม่บนเครื่องเดียวกันมีสถานะแยกกัน ไม่ใช้ flag เดียวทั้งเครื่อง; แก้ชื่อหรือข้อมูลร่างกายของโปรไฟล์เดิมไม่ reset สถานะ การเปลี่ยน camera/manual ไม่บังคับฝึกเต็มซ้ำ ให้ใช้คำแนะนำสั้นในหน้าพร้อมเล่นแทน
- tutorialVersion ใช้บอกเวอร์ชันที่เคยฝึก ไม่บังคับฝึกซ้ำเพียงเพราะมี deployment หรือเปลี่ยนเวอร์ชัน หากเปลี่ยนวิธีควบคุมจริงให้เสนอการฝึกใหม่แบบเลือกเอง
- การตั้งกล้อง/ตรวจ tracking พร้อมและ countdown ยังทำทุกครั้งที่จำเป็น แม้ข้ามบทฝึก ข้อมูลนี้อยู่เฉพาะเครื่อง/เบราว์เซอร์เดิม ถ้าล้างข้อมูลหรือเปลี่ยนเครื่องอาจเจอบทฝึกอีกครั้ง; กรณี storage ใช้ไม่ได้ข้ามซ้ำได้เฉพาะ session ปัจจุบันและต้องแจ้งว่าบันทึกไม่ได้

**ตรวจรับ**: หยุดฉากแล้ว input ยังทำงาน; รอเฉย ๆ หรือขยับผิดไม่ผ่านขั้น; ขยับถูกแล้วฉากเดินต่อเอง; กล้องหลุดไม่ผ่านขั้นและกลับมาฝึกต่อได้; ผู้เล่นใหม่เรียนรู้ครบจาก input ที่เลือก; รอบจริงยังประมาณ 180 วินาทีไม่รวมฝึก/พัก/countdown และไม่ pause ที่ประตู; บทฝึกไม่แตะสถิติหรือคลังข้อสอบจริง; กลับเมนูแล้วเริ่มใหม่ไม่ค้างสถานะฝึก

**จุดแก้**: `Practice.tsx`, `LearningGame.tsx`; เพิ่ม controller ฝึกแยกจาก `RunSession` ปัจจุบันคำนวณ activePlayMs จากระยะทาง/ความเร็ว จึงห้ามลด COURSE_SPEED ทั้งเกมเพื่อทำบทฝึก

## FFF-04 — เพิ่มไอเท็มและความท้าทาย

**งาน**

- เปลี่ยน type union สี่ชนิดเป็น catalog ที่มี stable ID, ชื่อไทย, model/icon, effect category, magnitude, คำอธิบายสั้น และ spawn weight
- ชุดแรก 10–12 แบบ: ผลไม้หลายชนิด ผัก อาหารมื้อสมดุล น้ำเปล่า นมไม่หวาน เบอร์เกอร์ พิซซ่า น้ำอัดลม และขนมหวาน ใช้โมเดลที่เด็กแยกออกจากกันได้จริง
- แยก “ความหลากหลายของภาพ” กับ “ความหลากหลายของผล” กลุ่มคืนสมดุลมีแรงต่างกัน กลุ่มเพิ่มค่าจำลองมีแรงต่างกัน น้ำเป็นตัวเลือกกลาง ไม่ใช้ภาพต่างกันแต่สุ่มผลกลับด้าน
- สื่อสารว่าเป็นกติกาจำลองและความพอดี ไม่ติดป้ายอาหาร/รูปร่างว่าเป็นคนดีหรือไม่ดี ไม่สอนว่าอาหารสุขภาพยิ่งกินยิ่งผอม
- สุ่มแถวแบบ seeded reproducible; seed เดียวได้ layout เดียว เพิ่มความท้าทายด้วยการเลือกระหว่างผลต่างระดับและการสลับเลน ไม่เพิ่มสิ่งกีดขวาง
- เสนอ 2 แถวต่อช่วงในข้อ 1–3 และ 3 แถวต่อช่วงในข้อ 4–10 ปรับหลัง playtest; เว้นแถวอย่างน้อย 2 วินาทีและไม่บังคับข้ามสองเลนแบบกระชั้นชิด
- ทุกแถวมีทางเลือกที่หลีกเลี่ยงผลเสียได้ และยังมีทางกลับสู่สมดุลหลังเลือกพลาด เก็บแถวสุดท้ายให้เสร็จก่อน quiz approach 6 วินาที ไม่ใส่ไอเท็มกวนการตอบ
- อ่านชื่อ/สัญลักษณ์ผลไอเท็มได้จากระยะกล้อง เพิ่ม pickup feedback ที่บอกชนิดและผลจริงที่ได้รับ

**ตรวจรับ**: เล่นหนึ่งรอบพบอย่างน้อย 6 ชนิดด้วย constraint ของ generator; ไอเท็มไม่ซ้อน gate; เส้นทางเล่นได้ด้วย camera latency จริง; เก็บหนึ่งชิ้นนับหนึ่งครั้ง; seed replay และ itemCounts ถูกต้อง

**จุดแก้**: `src/game/learning/types.ts`, `RunSession.ts`, catalog ใหม่ และโมเดลไอเท็มใน `src/game/three/GameEngine3D.ts`

## FFF-05 — เพิ่มแรงกระทบ BMI จำลอง

**ปัญหาปัจจุบัน**: `simulatedBmi = initialBmi × (1 + balance × 0.0015)` ไอเท็มเพิ่ม balance 10 จึงเปลี่ยนประมาณ 1.5% ของค่าเริ่มต้น ผลค่อนข้างเบา

**ค่าทดลองที่เสนอ**

| เหตุการณ์ | ผลต่อ balance ที่เสนอ |
|---|---:|
| ไอเท็มเพิ่มระดับปานกลาง | +18 |
| ไอเท็มเพิ่มระดับสูง | +28 |
| ไอเท็มคืนสมดุลปานกลาง | ขยับเข้า 0 สูงสุด 20 |
| ไอเท็มคืนสมดุลสูง | ขยับเข้า 0 สูงสุด 30 |
| น้ำเปล่า / ทางเลือกกลาง | 0 |
| พลาดจุดมื้อหลักที่ระบุไว้ | −18 |

- clamp balance ที่ −100…100; ทดลอง multiplier `0.0025` ให้เพดานค่าจำลอง ±25% จาก BMI เริ่มต้น ตัวอย่าง BMI เริ่ม 20 รับ +28 จาก balance 0 → 21.4 ไม่ใช่เปลี่ยนน้ำหนักจริง
- ไอเท็มคืนสมดุลต้องทำงานทั้งสองทิศ: balance +28 รับคืน 20 → +8; balance −28 → −8; ห้ามข้ามศูนย์เพราะกินของคืนสมดุล
- เป้าหมายเกมคือรักษา “สมดุลการเลือก” รอบค่าตั้งต้นของตัวละคร ไม่ใช่ลด BMI ให้ต่ำที่สุด หรือบังคับเด็กทุกคนไปที่ BMI ตัวเลขเดียว การคืน balance เป็น 0 ไม่แปลว่า BMI จริงอยู่ในช่วงสมส่วน
- แถบ BMI และสีต้องใช้ evaluator เดิมกับค่าที่แสดง ไม่เปลี่ยนเป็นเขียวเพียงเพราะ balance เป็น 0; แยก feedback “กลับมาสมดุลการเลือก” จากการประเมิน BMI ตามอายุ/เพศ
- แสดง delta ที่เกิดจริงหลัง clamp เช่น “BMI จำลอง +1.4” และ tween รูปร่าง/แถบ 300–500ms ไม่เปลี่ยนกติกาตาม animation
- ผลรอบแยก BMI จากข้อมูลที่กรอก กับ BMI จำลองหลังเล่น ไม่เขียนทับส่วนสูง น้ำหนักหรือโปรไฟล์ ไม่เพิ่ม Game Over เพราะ BMI ในรอบนี้
- ใส่ tuning ทั้งหมดใน config เดียว เพิ่ม bodyModelVersion/levelVersion และแยกกลุ่มคะแนนรุ่นใหม่เมื่อโอกาสได้คะแนนเปลี่ยน รักษาการอ่านรอบเก่า

**ตรวจรับ**: การเลือกผิด 2–3 ครั้งเห็นผลชัด แต่ยังแก้คืนได้; ค่าจำลองไม่หลุดเพดาน; pickup label ตรงผลจริง; รูปร่างเปลี่ยนไม่บังวิสัยทัศน์/ไม่เปลี่ยน collision; ไม่จัดเด็กผอมหรืออ้วนด้วยเกณฑ์ผู้ใหญ่

## FFF-06 — เอฟเฟกต์ตอบถูก/ผิด

- ตอบถูก: gate เรืองแสง, เครื่องหมายถูกและ “ถูกต้อง!”, particle burst สั้น, เสียงยืนยัน, คะแนนเพิ่มอย่างชัดเจน
- ตอบผิด: สัญลักษณ์ผิดและ “ลองจำคำตอบนี้ไว้”, pulse สีส้ม/แดงสั้น, แสดงคำตอบที่ถูกพร้อมเหตุผลสั้น และ “ผิดติดกัน 1/3” หรือ “2/3”; ข้อถัดไปตอบถูกต้องเห็น streak รีเซ็ต
- feedback หลักราว 1.5–2.5 วินาที เกมยังวิ่ง ไม่เปิด modal หยุด; เหตุผลยาวอ่านต่อหน้าผลรอบ
- ข้อสุดท้ายหรือผิดครบ 3: ล็อกผล session ทันที จากนั้นให้ presentation แสดง feedback ราว 0.8–1 วินาทีก่อนผลรอบ ไม่เดินระยะเพิ่มหรือเซฟซ้ำในช่วงนี้
- ใช้สีร่วมกับไอคอนและข้อความ ไม่มีแสงกระพริบถี่ ไม่เขย่าฉากแรง มี reduced-motion mode
- ผูกเอฟเฟกต์กับ event ID เช่น runId/questionIndex หรือ itemId เพื่อเล่นครั้งเดียว ไม่เรียกเสียง/particles ทุก React render

**ตรวจรับ**: ถูก/ผิดแยกออกแม้ปิดเสียง; feedback ไม่ทับคำตอบหรือ BMI; ข้อ 10 และ third-wrong เห็น feedback ก่อนผล; ไม่มี particle/เสียงค้างหลัง retry/ออกเมนู

## FFF-07 — Sound effects / ambient

- เสียงสั้นสำหรับ UI ยืนยัน, hold สำเร็จ, countdown, pickup แต่ละประเภทผล, quiz ถูก/ผิด, เส้นชัย และ Game Over
- Ambient เบาและ loop เนียนระหว่างเล่น; เพลงจังหวะสนุกเป็นอีก layer ได้แต่ไม่กลบคำตอบ/สัญญาณ; ลด ambient ชั่วคราวเมื่อมี quiz feedback
- Settings แยก SFX และ ambient/music พร้อม mute และจำค่าต่อเครื่อง; ค่าเริ่มต้นเสนอ SFX 60%, ambient 20%
- ตรวจ `SoundSynth.ts` ที่มีอยู่ก่อน reuse ส่วนที่เหมาะสม หลีกเลี่ยงเปิด legacy runner/boss music และระบบใหม่พร้อมกัน
- AudioContext ต้อง unlock/resume ภายใน tap/click เช่น OK ของ Objective หรือเปิดกล้อง การยกมือจาก pose ไม่ใช่ browser user activation; หาก unlock ไม่สำเร็จให้เกมเริ่มแบบเงียบได้ พร้อมทางเลือกเปิดเสียงเมื่อสะดวก ห้ามติด loading เพราะเสียง
- หยุด/fade เมื่อ pause, ซ่อนแท็บ, ออกเมนู และ cleanup nodes/timers เมื่อ unmount; จำกัดเสียง pickup ซ้อนกัน; กรณีโหลด asset ไม่สำเร็จยังเล่นเกมได้
- ใช้เสียงที่มีสิทธิ์ใช้งานและบันทึก provenance หรือ synth เอง ระบุโหลดล่วงหน้าและขนาดไฟล์ใน PR

แหล่งอ้างอิงข้อจำกัดเสียง: [MDN — Web Audio best practices](https://developer.mozilla.org/en-US/docs/Web/API/Web_Audio_API/Best_practices), [MDN — Autoplay guide](https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Autoplay)

**ตรวจรับ**: บน Safari/Chrome หลัง tap ตั้งค่าเริ่มต้น ยกมือเริ่มเกมแล้วมีเสียงได้; หาก browser ยังระงับเสียงก็เล่นต่อได้; mute ทุกช่องทำงาน; retry ไม่เกิด loop ซ้ำ

## ลำดับพัฒนาและการตรวจรับรวม

1. อ่านเอกสารเดิมและตรวจ working tree ก่อน ห้ามทับงานกล้องหรือ gameplay ที่ยังไม่ commit

4. FFF-04 catalog/spawn และ FFF-05 tuning ทำร่วมกัน ก่อนปรับคะแนน/version
5. FFF-06 visual feedback และ FFF-07 audio ผ่าน event seam เดียวกัน
6. ตรวจครบหนึ่งรอบจริงและเส้นทางแพ้ จากนั้นบันทึกหลักฐาน QA ก่อน deploy เมื่อได้รับคำสั่ง

**Automated tests ที่จำเป็น**

- Hold-start: สำเร็จครั้งเดียว, ลดมือ/reset, tracking ขาด/stale, สลับมือ, cancel/countdown, input fps ต่างกัน
- RunSession: delta/clamp/recovery สองทิศ, item นับครั้งเดียว, seeded layout เล่นได้, 10 gates, ข้อ 10 กับผิดครั้งที่ 3, ระยะ/เวลาประมาณ 180 วินาทีไม่เปลี่ยน
- บทฝึก: หยุดระยะ/เวลาแต่รับ input ได้, รอ/ขยับผิดไม่ผ่าน, ขยับถูกปล่อยฉากครั้งเดียว, tracking stale ไม่ผ่าน, ประตูทดลองหยุดแต่ประตูจริงไม่หยุด, ไม่แก้ profile/run/score/deck exposure, เริ่มจริง reset ทุกค่า, การข้าม/ฝึกใหม่
- Event integration: pickup/quiz เสียงและเอฟเฟกต์ครั้งเดียว, terminal feedback ไม่ทำ answer/run persistence ซ้ำ, audio failure ไม่บล็อก start
- Persistence: รอบเดิมอ่านได้, ผ่าน/ข้ามบทฝึกแล้ว retry/Play/reload ไม่ฝึกซ้ำ, Game Over ไม่ล้างสถานะ, โปรไฟล์ใหม่มีสถานะแยก, แก้โปรไฟล์หรือสลับโหมดไม่ reset, ออกจากการฝึกซ้ำไม่ล้างสถานะเดิม, storage ล้มเหลวยังข้ามได้ใน session เดิม, tutorial/audio preferences อยู่หลัง reload, คะแนนต่างเวอร์ชันไม่ปะปนโดยไม่มีป้าย
- รัน `npm run test` และ `npm run build` พร้อมแยก failure เดิมออกจากงานใหม่

**Manual QA**

- Desktop keyboard, มือถือ swipe, iPhone Safari, iPad Safari, Android Chrome พร้อมกล้องจริง
- ทดสอบ cold load / ครั้งต่อไป / ปฏิเสธ permission / กล้องโหลดช้า / สลับแท็บ / tracking หลุด / เปลี่ยนโหมด
- ผู้เล่นยืนห่างจอ อ่านข้อความ ยกมือเริ่ม ผ่านบทฝึก และเล่นครบโดยไม่เดินกลับมากด Start
- ตรวจเสียงบนอุปกรณ์จริง รวมกรณีเริ่มแบบ mute และปลด mute; ตรวจ performance ขณะกล้อง + 3D + particles + audio ทำงานพร้อมกัน
- จับภาพ HUD ในสภาวะหนักสุด: คำถามไทยยาว, คำตอบสามช่อง, กล้อง, feedback, BMI และจอ landscape เตี้ย
