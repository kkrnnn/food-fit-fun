# kcal balance and result cleanup

วันที่ 4 ตุลาคม 2026

ผู้ใช้ขอเอาคะแนนรอบ/คะแนนสูงสุดและสถานะ Supabase ออกจากผลรอบ พร้อมเพิ่มค่าหักของไอเทมออกกำลังกายให้มีผลต่อการเล่นมากขึ้น

## การแก้ไขในเครื่อง

- ลบคะแนนเกม/คะแนนสูงสุดและข้อความ cloud delivery จากหน้าสรุป คงผลคำถาม ระยะทาง kcal และแบบประเมินความสนุก
- ตามคำขอเพิ่มเติม: เอาส่วนที่มา FDA/USDA/Compendium และรหัสเวอร์ชันออกจากหน้าสรุป เก็บ source/model snapshots และเอกสารอ้างอิงสำหรับตรวจสอบเหมือนเดิม
- คงการบันทึกและ periodic retry เบื้องหลัง ข้อผิดพลาดการบันทึกในเครื่องยังแสดงเมื่อจำเป็น
- ข้อเสนอ balance: 1 pickup แทนกิจกรรมจำลอง 15 นาที โดยใช้ค่าต่อหนึ่งนาทีจากน้ำหนักและช่วงอายุเดิมคูณ 15 ไม่เปลี่ยนแหล่งอ้างอิงและไม่อ้างว่าเป็นพลังงานจากการกระโดดจริง
- โปรไฟล์ตัวอย่างเด็กชาย 12 ปี 40 kg: SHOES 105.268083333 kcal, DUMBBELL 42.67625 kcal, ROPE 101.000458333 kcal ต่อชิ้น
- รอบใหม่ใช้ model `nccor-youth+adult-met-gross-15min-v2`; รอบเก่ายังคง 1 นาทีหรือ fixed30 ตาม snapshot เดิม ไม่มี backfill
- รองรับ unsupported/null เหมือนเดิม ไม่สร้างค่าทดแทน การกระโดด/10 คำถาม/ผิดติดกัน 3 ข้อ/อาหารอ้างอิงคงเดิม
- API capability `exerciseEnergyVersion=3`; client รอใน outbox เมื่อพบ API รุ่นกิจกรรม 1 นาที เพื่อไม่ส่ง deductions ใหม่ให้ API ที่ปฏิเสธกติกาใหม่

## Validation

158 tests / 29 files, native Node runtime และ production build ผ่าน PostgreSQL 15 ชั่วคราวผ่านทั้ง 6 migrations และ 6 rollback-only SQL regressions รวมรอบ 1 นาทีเก่าและ 15 นาทีใหม่

Browser QA เล่นรอบจริงใน localhost จน Game Over: ตอบ 4/10 ข้อ ถูก 1 ข้อ ระยะทาง 40%; ไม่มีคะแนนรอบ/สูงสุดหรือ Supabase status ในผลรอบ [ภาพ](../qa/kcal-balance-clean-result.jpg)

QA fixture ใช้ public RunSession commands เก็บกิจกรรมทั้ง 10 ชิ้นด้วย profile เด็กชาย 12 ปี 40 kg: ค่า 15 นาทีรวม 852.1 kcal (ROPE3 = 303.0, DUMBBELL3 = 128.0, SHOES4 = 421.1) เทียบกับค่าเดิมรวม 56.8 kcal ตารางแสดงระยะเวลา 15 นาทีตรงกับ snapshot [ภาพกิจกรรม](../qa/kcal-balance-exercise-result.jpg)

## Release gate

Migration `20261004000400_exercise_game_balance.sql` และ register script เตรียมพร้อม แต่ **ยังไม่ applied live**. ตรวจ live ก่อนเปลี่ยนพบ 24 score / 4 feedback และ balance history ยัง false.

Auto-review ปฏิเสธ mutation เพราะผู้ใช้ยังไม่ได้ยืนยัน 15 นาทีและ live database change โดยชัดเจน รุ่น production ปัจจุบันยังเป็นค่ากิจกรรม 1 นาทีจาก release ก่อนหน้า ผู้ใช้สั่ง commit เวอร์ชันนี้เป็นจุด stable ในเครื่อง แล้วสร้าง branch ใหม่ทดลองภารกิจย่อย ยังไม่มีการเปลี่ยนฐานข้อมูลจริงหรือ deploy รุ่นทดลอง

## ข้อเสนอเพิ่มความท้าทาย — ยังไม่เปลี่ยนกติกา

ปัญหา: ปัจจุบัน kcal เป็นยอดสะสมที่ไม่มีภารกิจเก็บต่อ เมื่อเข้าใกล้เป้าผู้เล่นสามารถหลบอาหารทั้งหมดได้ การเพิ่มค่าหักออกกำลังกายอย่างเดียวจึงยังไม่สร้างเหตุผลให้เลือกอาหารต่อ

แนวทางแนะนำคือภารกิจเลือกอาหารช่วงสั้น 5 ช่วง ช่วงละ 2 คำถามตามระยะทางเดิม เช่น เก็บผลไม้ 1 ชิ้นกับผัก 1 ชิ้นในช่วงปัจจุบัน ก่อนเปลี่ยนเป็นโจทย์ชุดใหม่ การเก็บอาหารทำให้ต้องตัดสินใจว่าจะเพิ่ม kcal หรือกระโดดเก็บกิจกรรมเพื่อลดค่าก่อนเก็บอาหารตามโจทย์ครบ

- แสดงความคืบหน้าภารกิจและผลสำเร็จโดยไม่คืนกล่องคะแนน/สูงสุด
- สร้างรายการอาหารตามโจทย์ให้เจอได้จริงในช่วงนั้น มีเวลาหรือระยะทางให้เปลี่ยนเลน/กระโดด ไม่สุ่มให้ผู้เล่นไม่มีทางสำเร็จ
- ใช้ food category เพื่อสร้างทางเลือกที่หลากหลาย ไม่ใช้ kcal เพียงอย่างเดียวตัดสินคุณภาพอาหาร
- คง 10 คำถามตาม fixed distance, ไม่มี obstacles และตอบผิดติดกัน 3 ข้อ Game Over ตามเดิม ภารกิจเพิ่มใช้ผลสำเร็จในเกม ไม่เปลี่ยนเป็นคำแนะนำอาหาร/การออกกำลังกายจริง
- เพิ่มความเร็วเฉพาะช่วงเก็บของทีละน้อยได้ภายหลัง โดยยังคงเวลาตอบคำถาม 6 วินาทีและระยะที่ควบคุมได้

รอผู้ใช้เลือกแนวทางก่อนเพิ่ม missions/spawn/success rules
