# แผนปรับ gesture กล้อง, calibration และความลื่นของกราฟิก

วันที่: 2026-10-04
สถานะ: implementation บน `codex/camera-calibration-performance` แล้ว · ตรวจด้วยท่าจำลองและ browser · ยังรอทดสอบกล้องจริง

เปลี่ยนตามคำขอล่าสุด: ใช้การยกตัวแตะกรอบบนเพื่อสั่งกระโดด รองรับการเคลื่อนขึ้นช้า ๆ ไม่ต้องจับจังหวะกระโดดจริง ผลตรวจอยู่ใน `docs/qa/camera-calibration-performance-verification.md`

## เป้าหมาย

ผู้เล่นเข้าใจว่าต้องขยับแค่ไหนเพื่อเลือกซ้าย กลาง ขวา และกระโดด ระบบตั้งค่าตามท่าของผู้เล่นจริงก่อนเริ่มรอบ โดยเกมตอบสนองเร็วและกราฟิกมีจังหวะสม่ำเสมอขณะเปิดกล้อง

## สิ่งที่ตรวจพบก่อนเริ่มงาน

- `PoseMapper` ตั้งท่ากลางจากไหล่และสะโพกที่นิ่ง 1.5 วินาที เลือกเลนจากระยะไหล่เทียบกับความกว้างไหล่ ใช้ smoothing, hysteresis และ dwell 100 ms อยู่แล้ว แต่ไม่ได้ทดสอบระยะซ้าย/ขวาของผู้เล่นก่อนเริ่ม
- `JumpGesture` ตรวจไหล่และสะโพกที่ยกขึ้นพร้อมกันเทียบกับความสูงลำตัว ใช้ threshold ตามความไว มี cooldown และรอคืนท่าก่อนกระโดดครั้งถัดไป ยังไม่ได้เรียนรู้ท่ากระโดดเฉพาะผู้เล่น และการย่อตัวบางกรณีทำให้ baseline ถูกตั้งใหม่
- กล้องใช้ MediaPipe Lite, ย่อภาพด้านยาวสูงสุด 480 px และมี Worker พร้อมจำกัด inference ค้างพร้อมกันหนึ่งงานแล้ว Sampling interval ฝั่ง Worker 67 ms; fallback บน main thread 125 ms ตัวเลขนี้เป็นช่วงเวลาที่ตั้งไว้ ไม่ใช่ FPS ที่วัดได้
- ฉาก Three.js มีตัวเลือกคุณภาพสามระดับ แต่ยังไม่ปรับคุณภาพตามภาระงานอัตโนมัติ `renderLearning` สร้างแผนรายการ entity ทุกเฟรม และสร้าง/ทำลาย mesh เมื่อไอเทมหรือประตูเปลี่ยน ส่วน UI ส่ง snapshot ประมาณทุก 80 ms
- จุดเหล่านี้เป็นข้อมูลสำหรับออกแบบและวัดผล ยังไม่ได้ยืนยันว่าอะไรเป็นสาเหตุของอาการกระตุกจากอุปกรณ์จริง
- การแก้ modal ปัญหากล้องให้จำกัดเฉพาะ gameplay จากงานก่อนหน้ายังอยู่ใน working tree ต้องรักษาการแก้นั้นระหว่างทำงานนี้

## 1. เก็บ baseline ก่อนเปลี่ยนพฤติกรรม

ใช้เส้นทางเกมและ seed เดียวกันเพื่อเทียบโหมดปุ่ม, กล้อง Worker และ fallback ที่อุปกรณ์รองรับ เก็บผลช่วงวิ่ง เก็บอาหาร เก็บ exercise และเข้าประตูคำตอบ

วัด frame time median/p95, เฟรมเกิน 50 ms, inference time, อายุของผล pose เมื่อใช้สั่งงาน, จำนวน draw calls/triangles และการสร้าง entity ใช้ profiler แยก main thread, renderer และ inference

เครื่องมือวัดอยู่ในโหมดพัฒนา ไม่มีตัวเลขเทคนิคเพิ่มในหน้าที่ผู้เล่นใช้ ไม่บันทึกหรือส่งภาพกล้อง หากต้องเก็บข้อมูลเพื่อ replay ให้ใช้ชุด landmark จำลองก่อน และแยกการเก็บ landmark จริงเป็นงานที่ต้องมีขอบเขตชัดเจน

## 2. Modal calibration ขนาดใหญ่เมื่อกดเปิดกล้อง

เปิดโดยการกดเปิดกล้องหรือกดตั้งค่าใหม่ มีภาพกล้องใหญ่ คำสั่งทีละขั้น ตัวอักษรและปุ่มที่อ่านได้ขณะยืนห่าง ไม่มี skeleton

ภาพใช้สัดส่วนจริงและแสดงสามโซนซ้าย/กลาง/ขวา เส้นแบ่งต้องใช้พิกัดเดียวกับตัวเลือกเลน รวมการ mirror และขนาดภาพ ห้ามให้กรอบแสดงท่าหนึ่งแต่เกมตีความอีกท่าหนึ่ง ใช้จุดหรือเครื่องหมายเล็กแทนตำแหน่งลำตัว

ลำดับการตั้งค่า:

| ขั้น | คำสั่งหลัก | เกณฑ์ผ่าน | Feedback |
| --- | --- | --- | --- |
| เตรียมกล้อง | ยืนให้เห็นไหล่ถึงเอว | โหลดกล้องสำเร็จและพบลำตัวที่ใช้ได้ | ข้อความสถานะพร้อมคำแนะนำแสง/ระยะเมื่อจำเป็น |
| กลาง | ยืนตรงกลางให้นิ่ง | เก็บ baseline และ noise ของตำแหน่งนิ่ง | ช่องกลางเขียวพร้อม ✓ |
| ซ้าย | ขยับไปซ้ายในระยะที่สบาย | เก็บตำแหน่งซ้ายที่แยกจากกลางได้ชัด | ช่องซ้ายเขียวพร้อม ✓ |
| ขวา | ขยับไปขวาในระยะที่สบาย | เก็บตำแหน่งขวาที่แยกจากกลางได้ชัด | ช่องขวาเขียวพร้อม ✓ |
| กลับกลาง | กลับมาตรงกลาง | คืนเลนกลางได้และยืนนิ่งพร้อมทดสอบกระโดด | เครื่องหมายตำแหน่งกลับเข้าช่องกลาง |
| กรอบบน | ยกตัวให้จุดศีรษะแตะกรอบบนหนึ่งครั้ง | ตรวจพบศีรษะถึงกรอบ | เขียวพร้อม ✓ ทันที ไม่รอค้างท่า ลดตัว หรือทำซ้ำ |
| พร้อม | ตั้งค่าครบแล้ว | ผู้เล่นยืนยันด้วยปุ่มหรือยกมือค้าง | ปิด calibration และกลับไปขั้นเริ่มเล่น |

สีเขียวของงานที่ผ่านแล้วคงอยู่ ใช้ ✓ และข้อความร่วมกับสี ขั้นที่ยังไม่ผ่านแสดงคำแนะนำเฉพาะจุด สามารถลองขั้นนั้นใหม่ได้โดยไม่ต้องเริ่มใหม่ทั้งหมด

ระหว่าง calibration gesture ไม่เปลี่ยนเลนในรอบ ไม่เก็บไอเทม และไม่เริ่มเกม การยกมือยืนยัน calibration และการยกมือเริ่มเกมต้องเป็นคนละรอบลดมือ/ยกมือ

ถ้าเปิดกล้องหรือตรวจท่าไม่ได้ ให้แสดงปัญหาและปุ่มเปิดใหม่/ใช้ปุ่มแทนใน calibration เดิม Modal ปัญหาที่โผล่เองยังจำกัดเฉพาะระหว่าง gameplay ตามคำขอก่อนหน้า

## 3. เลือกเลนด้วยสามโซนที่เหมาะกับผู้เล่น

- อิงท่ากลางและระยะขยับซ้าย/ขวาที่เก็บได้ เพื่อกำหนดขอบเขตที่ผู้เล่นเข้าถึงได้สะดวก เก็บค่าแต่ละด้านแยกกัน รองรับระยะสองด้านไม่เท่ากัน
- เริ่มจากขอบเขตอิงขนาดลำตัวในขั้นทดสอบ แล้วคำนวณขอบเขตสุดท้ายจากตำแหน่งกลาง/ซ้าย/ขวาที่ผ่านการตรวจความเสถียร ต้องมีระยะแยกขั้นต่ำเพื่อไม่รับ noise เป็น calibration ที่สำเร็จ
- ใช้จุดกลางไหล่และสะโพกที่ผ่าน confidence check เป็นตัวแทนลำตัว ตรวจและเลือกน้ำหนักของสองจุดจากผลทดลองจริง
- คง hysteresis ระหว่างขอบเข้า/ออก ลดการสลับเลนเมื่อยืนใกล้เส้น ใช้ smoothing ตามเวลาและ dwell สั้น ปรับให้ได้ทั้งความนิ่งและเวลาตอบสนอง
- เลนเป็นตำแหน่งซ้าย/กลาง/ขวาจริง ผู้เล่นกลับกลางแล้วตัวละครกลับกลาง การขยับเร็วจากซ้ายไปขวาไม่ต้องค้างกลางเพื่อปลดล็อก
- ระงับการเรียนรู้ baseline ระหว่างกระโดด/ท่าหลุด และลดการเปลี่ยนเลนจาก noise แนวนอนขณะยกตัว โดยยังยอมให้ผู้เล่นเปลี่ยนเลนพร้อมกระโดดได้
- เก็บค่าพื้นฐานของรอบไว้ในหน่วยความจำ คง preference ความไวที่มีอยู่ การเปิดกล้องใหม่หรือเปลี่ยนมุม/ระยะต้องตรวจท่ากลางใหม่ ไม่ใช้ตำแหน่งภาพจากรอบเก่าโดยอัตโนมัติ

## 4. กระโดด: ยกตัวแตะกรอบบน

ตามคำขอผู้ใช้ล่าสุด ใช้จุดจมูก landmark 0 เป็นตัวแทนศีรษะ กำหนดกรอบเหนือระดับศีรษะในท่ายืนกลางตามขนาดลำตัวและ noise ไม่ต้องให้ไหล่และสะโพกยกพร้อมกัน ไม่ต้องผ่านเกณฑ์ความเร็วขึ้นหรือพิสูจน์ว่าเท้าพ้นพื้น ยืนปกติจุดศีรษะอยู่ใต้กรอบ และกรอบไม่เลื่อนตามขณะค้างเหนือกรอบ

การจูนล่าสุดยกกรอบสูงขึ้นจากระยะ 7.5% เป็น 15% ของความสูงลำตัวเหนือหัวในท่ายืนปกติ ค่าเดียวกันใช้ใน calibration และ gameplay ความไวปกติ หากหัวใกล้ขอบบนจะจำกัดระยะเพื่อให้กรอบยังอยู่ในภาพ

ลำดับตัวตรวจ: `ยืนพร้อม → จุดศีรษะถึงกรอบบน → ส่ง jump หนึ่งครั้ง → ลดศีรษะลงใต้กรอบ → พร้อมครั้งถัดไป`

- ยกตัวช้า ๆ ถึงกรอบก็สั่งได้ การย่อแล้วกลับท่ายืนกลางยังไม่ถึงกรอบ จึงไม่ถูกนับ
- จุดแสดงตำแหน่งศีรษะจริง การขยับเฉพาะไหล่โดยหัวอยู่ใต้กรอบไม่สร้าง jump จุดหัวที่ confidence ต่ำหรือพ้นภาพไม่สร้างคำสั่ง
- ค้างอยู่ในกรอบไม่สร้างคำสั่งซ้ำ ต้องลดตัวกลับต่อเนื่องและผ่าน cooldown ก่อนครั้งถัดไป
- เก็บ noise ขณะยืนเพื่อกำหนดกรอบเหนือระดับการสั่นปกติของผู้เล่น
- ผล pose เก่า, confidence ต่ำ หรือกล้องขาดช่วงไม่สร้าง jump อัตโนมัติ หลังขาดช่วงต้องกลับท่ากลางก่อน
- ยกมือค้างยังเป็น gesture สำหรับ OK/เริ่ม/เล่นต่อ แยกจากการแตะกรอบบน
- ขณะ calibration แสดงสามโซนและกรอบบนพร้อมสถานะสีเขียว Gameplay แสดงเฉพาะกรอบกับจุด ไม่มี skeleton หรือชื่อเลน

## 5. ลดอาการกระตุกตามผลวัด

ลำดับที่เสนอ:

1. รักษา Worker และการมี inference ค้างเพียงหนึ่งงาน ตรวจ fallback ที่ทำงานบน main thread ตามข้อจำกัดอุปกรณ์ ปรับความละเอียด/ความถี่ให้เหมาะกับเวลา inference ที่วัดได้ ไม่เพิ่มอัตราตรวจท่าโดยไม่ดูภาระ CPU
2. ให้ renderer เดินตาม render clock และรับผล pose ล่าสุดที่ยังใช้ได้ UI calibration อัปเดตประมาณ 10–15 ครั้ง/วินาที หรือเมื่อขั้น/เลน/ผลท่าเปลี่ยน ไม่บังคับให้ React render ทุกเฟรม
3. ถ้า profiler ยืนยันการสร้าง object/GC หรือ spawn เป็นจุดสะดุด ให้ reuse scratch objects และ pool/cache geometry, material, texture ของไอเทมกับประตู ต้องกำหนด ownership/dispose ให้ชัดเพื่อไม่ทำลาย resource ที่ยังใช้ร่วมกัน
4. เพิ่มคุณภาพอัตโนมัติสำหรับโหมดกล้อง ลด render resolution และเงาก่อน ลดรายละเอียดฉาก/เอฟเฟกต์เมื่อยังจำเป็น คงขนาดและความอ่านง่ายของไอเทม/ข้อความ มีช่วงสังเกตและ cooldown เพื่อไม่สลับคุณภาพไปมา
5. ลดงานฉากเมื่ออยู่เมนูหรือมี calibration/pause modal โดยคงภาพพื้นหลังที่สวยและวิดีโอกล้องที่ตอบสนอง เมนูไม่ต้องเรนเดอร์ 3D เต็มอัตราตลอดเวลา
6. หากอุปกรณ์ไปไม่ถึง 60 FPS ให้เลือก 30 FPS ที่สม่ำเสมอ โดยคงเวลาจริงของเกม ระยะทาง หน้าต่างตอบคำถามและการเก็บไอเทม

เป้าหมายเบื้องต้น: 60 FPS บนเครื่องที่รองรับ หรือ 30 FPS ที่สม่ำเสมอบนอุปกรณ์จำกัด; ลด frame-time p95 และเฟรมสะดุดเกิน 50 ms จาก baseline เป้าหมายเป็นเกณฑ์ทดลอง ยังไม่ใช่ผลที่ยืนยันแล้ว

## การตรวจรับเมื่อ implementation เสร็จ

- ทดสอบ behavior ที่ public seams: calibration transitions, zones, jump pulse/rearm, start/OK/recovery; ใช้ pose จำลองครอบคลุม jitter, กลับกลาง, ขยับด้านข้าง, ย่อ, ก้ม, ยกมือ, jump สองครั้ง, เฟรมหาย/เก่า และ mirror
- ทดสอบ flow UI: ผ่านครบก่อน OK, เฉพาะขั้นสำเร็จเป็นเขียว, ปุ่มลองใหม่, เมนูไม่เปิด modal ปัญหาเอง, camera error อยู่ใน setup, ท่าระหว่างตั้งค่าไม่เริ่มรอบหรือเปลี่ยนเกม
- ตรวจ responsive และความอ่านง่ายจากระยะยืนจริง ไม่มี skeleton และไม่เพิ่ม zone labels ใน preview ระหว่าง gameplay
- ทดสอบกล้องจริงหลายระยะ/แสง: เปลี่ยนเลนและกระโดดอย่างละสิบครั้ง เป้าหมายเบื้องต้นถูกอย่างน้อย 9/10 และไม่เกิด jump ปลอมขณะยืน/โยก/ยกมือ 30 วินาที ปรับเกณฑ์และรายงานแยกตามอุปกรณ์
- วัด response latency ของ input ถึงตัวละครบนอุปกรณ์จริง เป้าหมายทดลอง median ไม่เกิน 200 ms และ p95 ไม่เกิน 300 ms; ถ้าไม่ถึงให้รายงานแยก sampling, inference, smoothing/dwell และ rendering
- เทียบ performance ก่อน/หลังในฉากและคุณภาพเดียวกัน แล้วตรวจ auto quality แยกอีกครั้ง เพื่อให้รู้ว่าดีขึ้นจากอะไร
- ตรวจซ้ำว่า kcal, คำถาม, การเก็บ exercise และโหมดปุ่ม/ปัดจอยังทำงานตามกติกาปัจจุบัน
- Synthetic tests และ build ยืนยัน logic/compatibility ได้ แต่การจับท่าจริงและความลื่นต้องยืนยันจากกล้องและอุปกรณ์จริงด้วย
